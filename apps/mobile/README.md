# ESSENTIALS mobile

Expo Router app for guests, DJs, promoters, venue managers, door staff and admins.

## Native projects are disposable

`android/` and `ios/` are generated by `expo prebuild` and are gitignored. Running
`npm run prebuild` (`expo prebuild --clean`) **deletes both directories**, so never
put anything there that you want to keep — including signing keys.

## Android signing

Store builds use EAS-managed remote credentials. The project is linked as
`@gollapagus/essentials-app` (`f6163aa1-d793-4be0-bc36-ea8f29a65ad9`), and the
upload key is stored in EAS. EAS injects it after prebuild, so a clean prebuild
does not change how the app is signed.

The same upload key is backed up locally at:

- `credentials/essentials-upload.jks` — alias `essentials-upload`, valid 10,000
  days, SHA-256 `3B:01:52:BD:77:4F:59:41:33:98:5E:EA:FD:8F:16:8E:50:8B:A4:DC:A7:DC:47:E2:D0:A1:21:AC:4A:E7:12:15`
- `credentials/keystore.properties` — store/key passwords

`credentials/` is gitignored. Keep a copy somewhere safe outside this machine;
losing this key means a Play Console upload-key reset.

### Rotating the upload key

Only do this when rotating the key — re-uploading replaces the one Play expects.
Run from `apps/mobile`:

```bash
npx eas-cli@latest login
npx eas-cli@latest credentials --platform android
```

Choose **production → Keystore → Set up a new keystore**, answer **no** to
“Generate a new Android Keystore?”, then answer:

- keystore path: `credentials/essentials-upload.jks`
- keystore password: from `credentials/keystore.properties`
- key alias: `essentials-upload`
- key password: same file

Check it with `npx eas-cli@latest credentials --platform android` — the SHA-256
must match the fingerprint above.

### Build and submit

```bash
npm run build:android    # EAS production build → signed .aab for Play
npm run build:ios        # EAS production build → App Store archive
npx eas-cli@latest submit --platform android --profile production
```

`eas.json` sets `credentialsSource: "remote"` on every profile, so EAS always signs
from its stored credentials rather than anything left in `android/`. `production`
builds an app bundle and auto-increments `versionCode`; `preview` builds an
installable APK. `versionName` and the starting `versionCode` come from
`app.json`.

### Local builds

`npx expo run:android` and `npx expo prebuild` are for development and use the
template debug keystore. Do not ship those artifacts; use EAS for anything that
goes to Play.
